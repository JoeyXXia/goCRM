# DealFlow CRM · Day 10 客户与联系人

本轮从 2026-11-12 晚开始，完成记录日期为 2026-11-13（北京时间）。起点为 Day 9 提交 `f86c7045`。Day 编号按交付进度推进。

## 当前实现与最小方案

Day 9 已提供四级范围解析、按动作合并数据角色、查询 OR 分组及实时成员版本。Day 10 复用该范围过滤器和企业工作台，增加独立的客户、联系人表及 CRUD。客户编号、租户、负责人和部门由服务端填写，联系人通过客户根对象继承权限。

客户读取的默认范围与成员读取保持同一角色映射。客户写入授予销售本人、经理本部门及后代、管理员本租户全部，财务默认只读。创建仅授予主角色中的销售、经理和管理员。完整契约见 [接口边界](../../aiDoc/frontend-backend/boundary.md)。

## 可观察验收

| 条件 | 验证内容 |
| --- | --- |
| 销售无法填写权限归属字段 | 客户创建及更新提交 ownerId、tenantId、departmentId、code 均返回 400。正常创建返回服务端生成的业务编号及当前成员归属。 |
| 详情、更新和批量读取具有相同边界 | 同租户他人及异租户客户、联系人的详情与写操作被拒绝。批量混入这些 ID 后只返回可见记录。销售附加财务读取范围后可读本部门客户，但他人客户的 canUpdate/canDelete 为 false。 |
| 分页、排序与搜索遵守白名单 | 测试名称排序及总数，搜索不会返回其他负责人的客户。未知排序字段、重复参数、越界页码和 pageSize、伪造 scope/tenantId 均返回 400。 |
| 联系人跟随客户且关联受数据库保护 | 联系人不能改绑客户或租户。非法邮箱返回 400，更新可清空可选字段。跨租户客户、部门、负责人及联系人关联被外键拒绝。有联系人时删除客户返回 409，清空联系人后允许删除。 |
| Vue 页面可操作并清理跨企业状态 | 使用生产构建、Edge 和真实 MySQL 后端验证。浏览器会话由测试签名 JWT 启动，CRUD、搜索排序、只读状态和跨企业直接 URL 场景由浏览器脚本执行。 |

指定 Go 测试命令以 `-count=2` 通过，后端及两个 CLI 构建通过。包含新 CRM API 文件的限定 TypeScript 检查与 Vue 生产构建通过，Vue 组件由 Vite 编译和浏览器流程验证。最大长度且使用 JSON 转义的字段也通过 HTTP 创建验证。

最终浏览器脚本通过了真实 MySQL 客户与联系人新增、编辑、删除、搜索排序、只读能力、跨租户直接 URL 拒绝和企业切换。预期 404 使用 GVA 原有错误提示，确认后可以继续操作。夹具 Go 测试正常结束，本轮数据清理成功，临时会话文件及执行文件已移除。本地截图保存在 `output/day10-customer.png`。

## 复现

准备专用库 `dealflow_crm_test`，设置 `DEALFLOW_TEST_DSN`。在 server 目录执行常规回归与迁移。

```sh
go test -mod=readonly ./cmd/dealflow-migrate ./cmd/dealflow-tenant ./router/system ./service/tenant -count=2 -v
go build -mod=readonly . ./cmd/dealflow-migrate ./cmd/dealflow-tenant
go run -mod=readonly ./cmd/dealflow-migrate -tenants
```

浏览器夹具仅在显式设置环境变量时启动，常规 CI 会跳过该服务。在 server 终端运行以下 PowerShell 命令，等待 ready 提示。

```powershell
$env:DEALFLOW_BROWSER_FIXTURE_FILE = Join-Path (Resolve-Path '..') '.local/day10-browser.json'
go test -mod=readonly ./cmd/dealflow-migrate -run '^TestDay10BrowserFixture$' -count=1 -v -timeout=10m
```

另一个终端在 web 目录执行 `npm run typecheck`、`npm run build`，启动预览。夹具后端监听 127.0.0.1:8888，前端通过原有 /api 代理连接。

```powershell
$crmBuild = (Resolve-Path './dist').Path
node ./node_modules/vite/bin/vite.js preview --mode development --outDir $crmBuild --host 127.0.0.1 --port 4176 --strictPort
```

在仓库根目录运行浏览器脚本，准备步骤把临时 JWT 写入本地执行文件。浏览器结束后触发后端清理，仅删除本轮创建的账号、租户、客户与联系人。执行文件用完应移除。

```powershell
node web/tests/prepare-day10.cjs
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day10 open http://127.0.0.1:4176/ --browser=msedge
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day10 run-code --filename=.local/day10-browser-run.js
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day10 close
Remove-Item -LiteralPath '.local/day10-browser-run.js'
```

## 最可能失败的边界

联系人直接 URL 或批量查询绕过客户根对象、列表有范围而更新没有范围、把可读范围误作可写范围，以及从请求体批量赋值归属字段，是本轮主要回归目标。

客户删除采用先清理联系人的方式，负责人转移和跟进记录按 Day 11 推进。浏览器会话使用测试签名 JWT，验证码登录流程尚待验证。用户取消写请求时，服务端已经开始执行的事务可能继续完成。
