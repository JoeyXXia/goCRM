# DealFlow CRM · Day 8 部门树与成员管理

日期 2026-11-11（北京时间）。起点为已推送的 Day 7 提交 `ebc04b7e`。

## 当前实现与最小方案

Day 7 已建立 JWT、活跃成员查询和 Casbin 动作校验的链路。此前部门只有查询和改名入口，成员通过开通服务与演示种子写入。Day 8 复用同一企业路由和事务服务，增加部门树、成员生命周期及权限版本。新增管理入口供企业管理员使用。

## 可观察验收

| 条件 | 本地实测 |
| --- | --- |
| 部门树可创建、查询、修改和删除，祖先顺序正确 | 创建三级树，祖先查询返回直属父部门、根部门。带子部门或成员的删除返回 409，解除依赖后空叶部门删除成功。 |
| 同名部门隔离，跨企业父部门与树环被拒绝 | A/B 同名、同编码部门分别创建成功。同企业重复编码返回 409，跨企业父部门返回 404，自引用及将根移到后代下返回 409。 |
| 成员归属、角色与权限版本一致 | 新成员版本为 1。更新部门及提升角色、再禁用后版本为 3。重复成员返回 409，跨企业部门归属返回 404，销售直接操作管理 API 返回 403。 |
| 禁用与移除影响旧令牌的新请求 | 对既有签名 JWT，新增成员后可以访问 A，禁用后立即返回 403，重新启用后恢复，移除后再次返回 403。 |
| 并发操作保留管理员并避免树环 | 两个独立连接并发将两个部门互设父部门，一次成功、一次冲突。两个管理员并发停用自己，一次成功、一次冲突，回读恰好保留一名活跃管理员。另验证其他管理员账号被冻结时，移除当前有效管理员仍返回 409。 |

MySQL 版本为 8.0.44。下列 Go 包使用 `-count=2` 连续通过，后端和两个 CLI 构建通过。迁移在新测试与旧回归中重复执行成功。首轮并发用例发现测试连接池早于清理回调关闭，已调整回调顺序并重跑。对首轮遗留夹具按已核实的 ID 清理，回读 Day 8 临时租户及账号均为 0。

Swagger 的 Go 嵌入版与 JSON 的 paths、definitions 核对一致，YAML 与 JSON 的 DealFlow 路由和组织模型也核对一致。最终迁移命令输出 001、002、003 均已验证。

## 复现

准备专用库 `dealflow_crm_test` 和 `DEALFLOW_TEST_DSN`，在 `server` 中执行。

```sh
go test -mod=readonly ./cmd/dealflow-migrate ./cmd/dealflow-tenant ./router/system ./service/tenant -count=2 -v
go build -mod=readonly . ./cmd/dealflow-migrate ./cmd/dealflow-tenant
go run -mod=readonly ./cmd/dealflow-migrate -tenants
```

API 路径、输入字段和错误约定见 [接口边界](../../aiDoc/frontend-backend/boundary.md)。组织写入使用 GVA 已有账号，不符合启用条件的账号返回 400。关闭成员状态时可以处理其已冻结的 GVA 账号。

## 最可能失败的边界

树移动和管理员撤销必须经过获得租户行锁后的检查。绕开该服务直接写数据库会绕开树环和最后管理员业务规则，同租户关联仍由数据库外键保护。成员禁用影响后续请求，已经开始执行的请求具有各自的上下文。

MySQL DDL 独立提交，003 的两次 ALTER 可在中断后继续执行，登记版本前会核对新增列、默认值与父部门外键。部署测试库时需要 ALTER、INDEX、REFERENCES 和组织操作所需的 DML 权限。

本轮验证了后端 HTTP 入口及数据库并发。组织管理的前端页面和浏览器操作本轮未测。提交前的结果来自本机，远端工作流结果以 GitHub Actions 为准。
