## 实测验收

| 可观察条件 | 本地结果 |
| --- | --- |
| 从 A 切到 B 后，旧结果不能覆盖当前页 | Edge 运行生产构建。保持 A 的部门请求进行中，切到 B 后观察到 A 请求取消。B 部门显示后放行 A，页面仍只显示 B，改名入口隐藏，取消也未弹出全局错误。 |
| 无权限用户直达页面被拒绝 | 未登录直达改名页重定向登录。B 销售直达改名页看到拒绝提示，浏览器未发送部门请求。A 管理员从同一路由保存后看到更新的名称。 |
| 刷新恢复有效企业 | B 保持可用时刷新恢复 B。工作台列表撤下 B 后，刷新回退到仍有效的 A。浏览器夹具包含两个相邻的大整数 ID，菜单请求中的值与原字符串一致。 |
| T01 与 T04 基础回归 | 真实 MySQL 8.0.44 配合签名 JWT 跑两轮。跨企业部门查询与写入被拒绝，B 数据保持原值。企业发现过滤禁用成员、企业及禁用或软删除账号，并拒绝平台身份、伪造租户选择和无效 token。既有平台和 GVA 示例客户边界继续通过。 |
| T02 基础回归 | 数据库接受合法成员关系，对 A 成员关联 B 部门的新增及 B 成员改绑 A 部门的更新均返回外键错误。回读成员记录与变更前一致。 |

Go 服务和两个 CLI 构建通过，前端类型检查与生产构建通过。Swagger 的 Go 嵌入版、JSON 和 YAML 对企业发现接口及响应类型的定义一致。

## 复现

按 [Day 2 报告](2026-11-08-day2.md) 准备独立 MySQL 测试库并设置 `DEALFLOW_TEST_DSN`。在 `server` 中执行下列命令。现有 GitHub Actions 基础工作流会运行同一组 Go 测试。

```sh
go test -mod=readonly ./cmd/dealflow-migrate ./cmd/dealflow-tenant ./router/system ./service/tenant -count=2 -v
go build -mod=readonly . ./cmd/dealflow-migrate ./cmd/dealflow-tenant
```

在 `web` 中执行 `npm run typecheck` 和 `npm run build`，再运行 `npm exec -- vite preview --mode development --host=127.0.0.1 --port=4176 --strictPort`。从仓库根目录运行浏览器夹具。

```sh
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day6 open http://127.0.0.1:4176/ --browser=msedge
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day6 run-code --filename=web/tests/day6-browser.js
npx --yes --package @playwright/cli playwright-cli -s=dealflow-day6 close
```

浏览器测试使用模拟 API 响应来控制返回顺序，并单独用真实 MySQL 和签名 JWT 验证服务端。尚未在同一次浏览器会话中使用真实账号完成登录与改名，也未验证服务端已开始执行的写操作在客户端取消时的时序。远端 Actions 由推送触发，本报告记录的是提交前的本地结果。
