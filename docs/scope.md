# 业务故事与边界

2026-11-08 当前范围为 Day 2 的数据库迁移与测试环境。套餐、工作流、异步任务、微服务、Kafka、Kubernetes 保留在 [扩展实施计划](planning/DealFlow-CRM-扩展实施计划.md) 中，作为未来路线。

晨星设备（A）的销售 Alice 创建客户与商机、提交合同；经理 Bob 审批固定合同版本；财务 Carol 按订单应收登记回款。远舟服务（B）的用户无法访问 A 的数据。三类入口共用一套应用：平台运营管理租户元数据，企业管理处理组织与销售，员工工作台呈现授权待办。平台角色默认无企业业务访问权。

P0：可信租户/成员、角色与数据范围，客户与商机，合同版本审批，订单及分期应收，回款与一次全额冲正，基础报表；以真实 MySQL 验证隔离、并发、回滚。新增分期交付：套餐席位/续期/到期、配置化顺序工作流、持久任务、独立异步服务、Kafka 与 Kubernetes。延后：任意脚本/拖拽工作流设计器、真实支付/银行/电子签章、完整库存/总账、分库分表与 AI 助手。

必须保持的不变量：

- 服务端核验租户成员；缺可信 TenantContext 默认拒绝。tenant 与动作/记录范围同时成立。
- 业务关联租户一致，平台与企业授权分离；菜单隐藏不代替 API 授权。
- 审批冻结版本，禁止自审；有效确认订单总额不超过已批准金额。
- 金额使用 int64 分 / MySQL BIGINT，API 十进制字符串，前端新业务使用 TypeScript。
- 回款幂等与业务凭证双重防重；不超收；冲正保留历史。
- 关键业务、审计、outbox 同事务；不以 Redis 或 mock 证明数据库正确性。
- 业务日期 Asia/Shanghai，事件时间 UTC；结果与性能只记录实际证据。

Day 1 最小顺序：固定源码 → 核查许可/工具/调用链 → 锁依赖与本地配置 → 编译/运行/原始登录验收 → 记录进度。涉及 API、表、状态均为上游原有项，无新业务契约。

Day 2 的验证范围及复现方法见 [Day 2 报告](progress/2026-11-08-day2.md)。S1 归档见 [范围记录](progress/2026-10-25-scope-reset.md)。
